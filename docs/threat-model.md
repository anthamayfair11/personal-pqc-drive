# 脅威モデル

Personal PQC Drive が「何を守り、何を守らないか」を明示する。過信を避けるため、防御対象外を意図的に詳しく列挙する。

## 防御対象

- **サーバー運営者による中身の閲覧**: サーバーには暗号化済みバイナリしか渡らない。運営者は復号できない
- **サーバー側の自動コンテンツスキャン**: CSAM 検知システム等のスキャンは暗号文に対して無力
- **サーバー侵害時のデータ流出**: 攻撃者がサーバーを掌握しても、得られるのは暗号化済みバイナリのみ。受信者の秘密鍵がなければ復号不可
- **通信経路上の盗聴**: HTTPS 前提。加えてペイロード自体がエンドツーエンドで暗号化されている
- **将来の量子コンピュータによる収穫攻撃(HNDL)**: 通信を記録して後で量子計算機で復号する攻撃に対し、ML-KEM-768 を最初から使うことで防御。古典暗号(X25519)が将来破られても、ハイブリッド構造により ML-KEM 側が守る
- **URL の傍受**: URL にはファイル ID しか含まれない。URL を傍受しても、受信者の秘密鍵(IndexedDB に保管)がなければ復号できない

## 防御対象外(明示)

以下は本アプリの設計範囲外であり、保護を保証しない:

- **エンドポイント侵害**: 受信者・送信者のマルウェア感染、ブラウザ自体の脆弱性、OS レベルの侵害
- **受信者の悪意**: 復号後に受信者が別経路で内容を漏洩すること(これは技術的に防げない)
- **秘密鍵の物理的・社会的奪取**: IndexedDB への直接アクセス、PC の盗難、強要等による秘密鍵の取得
- **URL 共有チャネルのセキュリティ**: URL を送る経路(メール・メッセンジャー)の安全性はユーザーの責任。ただし URL だけでは復号できないため、傍受単体では被害にならない
- **物理アクセスを伴う攻撃**: ロック解除済みの端末への物理アクセス等
- **メタデータの推測攻撃**: ファイルサイズ(暗号文長から概算可能)、アップロード時刻、IP アドレス等からの推測。これらを隠すパディングや匿名化は実装していない
- **秘密鍵の喪失**: 受信者が秘密鍵をバックアップせずに IndexedDB を消失した場合、過去のファイルは復元できない(検閲フリーの代償として明示)
- **DoS 攻撃・ストレージ枯渇攻撃**: 大量アップロードによるサービス妨害やストレージ圧迫への対策は最小限(合計サイズ上限のみ)

## 暗号実装に関する注意

- 暗号プリミティブは [@noble](https://github.com/paulmillr) シリーズ(監査済み・純 JS 実装)と WebCrypto API に依存し、**プリミティブの独自実装はしていない**(「自分で暗号を実装しない」原則)
- ただし、それらを組み立てる部分 —— ハイブリッド鍵交換のロジック、HKDF のドメイン分離、ファイルフォーマット、エラーハンドリング —— は独自実装であり、**第三者によるセキュリティ監査を受けていない**
- ML-KEM-768 の implicit rejection 特性により、不正な暗号文に対しても復号関数は例外を出さず、最終的に AEAD タグ検証で失敗する(詳細は [crypto-spec.md](crypto-spec.md))

## 位置づけ

本アプリは**個人プロジェクト**であり、商用利用や、漏洩が深刻な結果を招く機密データの本番運用は想定していない。「ゼロ知識 + ハイブリッド PQC をきちんと実装する」ことを主目的とした検証・学習・公開のためのプロジェクトである。

セキュリティ上の問題を発見した場合は、GitHub Issues または作者の連絡先(README 参照)まで報告してほしい。
